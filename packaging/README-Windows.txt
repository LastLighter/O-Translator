# O-Translator（Windows 客户端）使用说明

## 启动

双击 `O-Translator.exe`。程序在托盘后台启动，**不会自动打开主窗口**，也不会
弹出浏览器页面；客户端会在后台自动启动本地翻译服务（127.0.0.1:8765），不需要
另外开命令行窗口。需要工作台时，双击托盘图标或从托盘菜单选择「打开主窗口」。

程序是单实例的：重复双击同一个 `O-Translator.exe` 不会启动第二个托盘图标、
截图遮罩或后端服务，只会把已经运行的主窗口唤到前面。

首次启动稍慢属于正常现象：OCR 使用 ONNX Runtime，第一次推理会加载 PP-OCR
模型（有 GPU 时还包括 CUDA/cuDNN 内核），约 1–3 秒，之后恢复正常。中文、英文、
日文和小语种拉丁文字使用随包内置的 PP-OCRv6 small 模型，**不需要下载**；
韩文、俄文等会按需下载 PP-OCRv5 模型到程序目录下的 `models/rapidocr/`。
LaMa 去字模型已经随压缩包内置，**不需要联网下载**。
如果 OCR 模型下载失败（例如 Clash 只代理了浏览器），可在程序目录新建 `.env`，
写入 `OTR_PROXY=http://127.0.0.1:7897`（按实际代理端口修改），再重启程序。

## 三种用法

| 模式 | 操作 |
|---|---|
| 手动图片 | 在「手动上传」页选择图片，或把图片拖进窗口，或按 `Ctrl+V` 粘贴 |
| 框选翻译 | 按 `F2`（可改），鼠标移到目标上会自动高亮窗口/控件；单击或空格截取高亮层，滚轮切换层级，拖拽可手动框选 |
| 自动监控 | 选定一个固定区域，区域内容变化时自动重新识别并翻译 |

截图遮罩里的操作：

- **移动鼠标**：自动识别并高亮光标下最内层的窗口或控件（Win32 子窗口 +
  UI Automation，兼容 Chrome/Electron、Office、WPF 等现代界面）。按下 F2
  时指针所在的位置就是第一帧高亮的位置。
- **左键单击 / 空格**：锁定当前高亮的窗口/控件（不会立刻翻译），随后出现
  操作栏；再点「翻译」或按 Enter 才确认。
- **按住左键拖拽**：忽略自动识别，手动框选任意区域；松开后锁定选区并显示
  操作栏，而不是直接开始翻译。
- **操作栏**：自动选择离屏幕边缘较远的一侧，放在选框外；选框贴近屏幕边缘时
  会收进选框内。按钮为「翻译 / 保存 / 退出」，「保存」会把当前选区存成 PNG。
- **锁定后按住左键拖动选框内部**：整体移动选区。
- **滚轮 / Tab / Shift+Tab**：从控件 → 客户区 → 窗口 → 整个屏幕逐层切换。
- **右键**：锁定状态先回到自由选区，自由选区再按一次退出；**Esc** 同理。
- **Enter**：未锁定时先锁定整个屏幕，锁定后再次按 Enter 确认。
- 如果目标程序以管理员权限运行，Windows 可能拒绝普通权限进程读取它的
  UI Automation 树；此时仍会退回 Win32 窗口/控件矩形，功能不会中断。

- 鼠标移到托盘图标可打开菜单：框选、开始/暂停监控、点击穿透、退出。
- 关闭主窗口只会隐藏到托盘；要完全退出请用托盘菜单的「退出」。
- 截图翻译时主窗口不会自动弹出，结果直接显示在译文浮窗中；需要工作台时从托盘打开。
- 译文浮窗贴靠截图区域，图片外沿带一层蓝色光晕；浮窗没有悬停标题栏，
  直接按住图片即可拖动，右键可「保存图片 / 关闭浮窗」（Ctrl+S / Esc 同样可用）。
- 自动监控的浮窗默认开启鼠标穿透，鼠标可直接操作下方内容；需要拖动或关闭时，
  请在托盘菜单关闭「浮窗鼠标穿透」。手动框选的结果默认可直接拖动。
- 浮窗右下角的缩放手柄可调整大小并脱离截图区域；点击穿透开启时该手柄仍可使用。

## DeepSeek API Key（环境变量）

客户端不保存、不写死任何 Key，翻译服务只从环境变量读取：

- `DEEPSEEK_API_KEY`（推荐）
- 或 `OTR_DEEPSEEK_API_KEY`

Key 需要设置成 **用户级环境变量**（设置后新启动的程序才能读到）：

```powershell
[Environment]::SetEnvironmentVariable('DEEPSEEK_API_KEY', 'sk-你的Key', 'User')
```

也可以在「系统属性 → 高级 → 环境变量」里添加。设置完成后重新打开
`O-Translator.exe` 即可；界面右上角/日志里如果显示 DeepSeek 已配置，说明读取成功。

没有 Key 时程序仍可运行：能完成 OCR、去字和排版，但会保留原文，不调用翻译。

## 数据目录

exe 同目录下会自动创建：

- `data/`：任务结果、截图、`desktop-backend.log`（后端日志）
- `models/`：可写的模型目录。LaMa 去字模型已内置在 `_internal/models/lama/`
  （约 196 MB 的 `lama_fp32_sim.onnx`），**解压即用，不会触发下载**；
  PP-OCRv4/v5 等非内置 OCR 模型下载到 `models/rapidocr/`，也可手动放入。
  可通过 `OTR_LAMA_PRECISION` 选择 FP32/FP16/INT8 变体
  （FP16/INT8 需自行验证质量，CPU 上默认 FP32 最稳）。

因此请把整个文件夹放在**可写**的位置（例如 D 盘或桌面），不要放进
`C:\Program Files` 这类需要管理员权限的目录。

## NVIDIA GPU 加速

如果程序目录下存在 `gpu_runtime\`，启动时会自动检测并优先使用
`CUDAExecutionProvider`。本压缩包若包含该目录即已内置；没有时，可把
`O-Translator-gpu-runtime-cuda12.zip` 解压到 `O-Translator.exe` 同级：

1. 确认 `gpu_runtime\` 与 `O-Translator.exe` 同级；
2. 重新启动程序；
3. 如果驱动/CUDA 运行库不兼容，会自动回退 CPU，不会崩溃。

实测 RTX 5060 Laptop：LaMa 单次推理从约 2.1 秒降到 **0.21–0.30 秒**；
PP-OCR 检测 + 识别约 **65–120 毫秒**（900–1400 px 页面），漫画任务端到端
约 1.2 秒。可设置 `OTR_DISABLE_GPU=1` 强制 CPU，
或用 `OTR_GPU_RUNTIME_DIR` 指向自定义的 `gpu_runtime` 目录。

> RapidOCR 与 LaMa 共用同一个 ONNX Runtime CUDA 运行库，OCR 不再依赖
> PaddlePaddle，也不需要单独的 OCR GPU wheel。

## 两段式显示（预览 + 精修）OCR 和翻译完成后，译文会先以「纯色/快速修复背景」立即显示（预览）；
LaMa 在后台继续精修复杂背景，完成后浮窗会以淡入方式换成最终结果。
纯色 UI、游戏聊天框、漫画对话框会自动跳过 LaMa，通常 15–30 ms 完成去字；
只有复杂网点/插画背景才会调用 LaMa。可用 `OTR_INPAINT_FAST_STDDEV` 调整
「简单背景」的判定阈值（默认 24，越小越保守）。

## 已知限制

- LaMa 只在复杂纹理背景上运行；纯色/简单背景使用快速 Telea/纯色填充。
  复杂背景在 CPU 上单次推理约 3–6 秒（取决于机器负载），预览会先显示，
  避免一直黑屏等待。
- 日文竖排漫画建议在「源语言」选择「日本語」或场景选择「漫画」；RapidOCR 会把
  竖排列旋转后再识别，自动模式检测到假名时也会切换到日文识别模型。
- 需要联网：仅首次使用韩文/俄文等非内置 PP-OCR 模型时会下载权重；中文、英文、
  日文、拉丁语系和 DeepSeek 翻译不需要额外 OCR 模型下载。**LaMa 模型不需要联网**。
- 本程序是本地工具，翻译服务只监听 127.0.0.1，不会对外网开放。
- 若被杀毒软件/Windows SmartScreen 拦截，请将整个程序目录加入信任列表，
  或点击「更多信息 → 仍要运行」（PyInstaller 打包程序常见误报）。

## 自检

如果识别或翻译异常，在程序目录打开 PowerShell 运行：

```powershell
.\O-Translator.exe --doctor
```

它会打印运行环境、依赖版本、ONNX Runtime 执行提供器以及 RapidOCR 初始化结果，
便于定位问题。
